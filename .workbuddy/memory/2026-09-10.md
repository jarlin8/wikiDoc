### ⚠️⚠️ 重大事故与根因：`\r\r\n` 换行损坏（务必牢记）

**现象**：用户反馈"表格混乱不堪、根本无法渲染"。

**根因**：112 个文件的行尾从 `\r\n` 被写成了 **`\r\r\n`**（CR CR LF）。
CommonMark 把 `\r`、`\n`、`\r\n` 都视为行结束符 → `\r\r\n` = 3 个行结束符 → 每行后凭空多出 **2 个空行** → 所有多行结构（表格/列表/引用/代码块）全部被拆散、无法渲染。

**这是上一轮 V5 脚本引入的回归**：`fix_mdx_v5.py` 用
```python
raw = path.read_bytes(); text = raw.decode("utf-8")   # 保留 \r\n
...
path.write_text(text, encoding="utf-8")               # Windows 下把 \n → \r\n
```
读时不归一化、写时又转换 → `\r\n` 变成 `\r\r\n`。

**修复**：`repair_crlf.py` 二进制读写，`\r\r\n` → `\r\n`，112 个文件。

**铁律（本项目所有脚本必须遵守）**：
1. 读写 Markdown **一律二进制**（`read_bytes`/`write_bytes`），或全程 `newline=''`；
2. 若用文本模式，读时归一化 `\r\n`→`\n`，写时必须显式 `newline=''`（或自己 `\n`→`\r\n`）——**绝不混用** `read_bytes().decode()` + `write_text()`；
3. 仓库统一 CRLF（`core.autocrlf=true`，无 `.gitattributes`）。

### wiki 链接的两个致命细节（务必牢记）
1. **插件默认把目标里的空格替换为 `-`**（`name.replace(/ /g,'-')`）。
   所以 `[[exness-trader/股票 | 股票]]`（`|` 前带空格）→ 目标 `exness-trader/股票 ` → 生成 `/exness-trader/股票-` → **断链**！
   正确写法：`[[exness-trader/股票|股票]]`（`|` 前**绝对不能有空格**）。
2. **表格单元格内不能用带别名的 wiki 链接**。
   原因：插件用 `|` 分隔目标/别名，而 GFM 表格也用 `|` 分隔单元格，两者在分词阶段冲突，无法同时满足——转义成 `\|` 又会让 `\` 混进链接目标（同样断链）。
   **解决**：表格内改用标准 Markdown 链接 `[股票](/exness-trader/股票)`（已验证路由存在）。共修正 8 处。

- 断链检测：Docusaurus 构建时的 broken-link 检查会暴露此类问题，是最终验收手段。
