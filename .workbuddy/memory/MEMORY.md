## 1. 侧栏与分类（`sidebars.js`）

- 侧栏是**显式分类树**，不是 autogenerated。**新增文档必须手动登记**，否则不显示（且不报错）。
- 二级分类暂用**显式列表**（用户决定日后按需再改）。它们是**虚拟分类**（对扁平目录的人工分组），**不能**用"建 index.mdx"实现。

### ⚠️ 一级分类约定（2026-09-16 最终版，**已推翻同日的 generated-index 方案**）

| 项 | 规定 |
|---|---|
| `link` 类型 | **必须是 doc 型**，指向该目录自己的索引页。**不要用 `generated-index`** |
| URL | 保持短路径，**不带 `/category/` 前缀** |
| 依赖机制 | Docusaurus 的 `folder/folder` 折叠规则：`docs/guides/guides.mdx` → `/guides`（**该文件无需写 slug**） |
| 索引页渲染 | 统一用 `<SectionIndex section="..." />`，样式对齐首页 `index.mdx`（Hero + 卡片网格 + 分组链接） |
| 索引页 frontmatter | **必须**带 `hide_table_of_contents: true`（一级目录一律不要右侧 TOC） |
| 数据源 | `src/data/sections.js`，由 `.workbuddy/gen_section_index.js` **自动生成**，勿手改 |

当前 5 个一级分类（**新增前先查重**）：

| 分类 | link 指向的索引页 | 最终 URL |
|---|---|---|
| 深度指南 | `guides/guides` | `/guides` |
| EXNESS 客户帮助 | `exness-trader/exness-trader` | `/exness-trader` |
| EXNESS 代理帮助 | `exness-agent/exness-agent` | `/exness-agent` |
| AI 与工具 | `ai-tools` | `/ai-tools` |
| 纽时播报 | `nytimes/nytimes` | `/nytimes` |

**新增一级分类的操作步骤**：
1. 建 `<目录>/<同名>.mdx`（如 `docs/foo/foo.mdx`），frontmatter 加 `hide_table_of_contents: true`，正文就一行 `<SectionIndex section="foo" />`
2. 在 `.workbuddy/gen_section_index.js` 的 `SECTION_META` / `CAT_ICON` / `CAT_DESC` / `QUICK` 中补元数据
3. 跑 `node .workbuddy/gen_section_index.js` 生成数据
4. 在 `sidebars.js` 加分类，`link: { type: "doc", id: "foo/foo" }`

**样式一致性**：`src/components/SectionIndex/styles.module.css` 与 `src/components/Homepage/styles.module.css` 是同一套视觉语言（同色板、同卡片圆角/阴影/悬停、同胶囊链接），改动其一需同步另一。

> 教训：曾把"一级目录做成 generated-index"理解成用户诉求，实际用户要的是**在既有目录页上改造**（`/exness-agent` 这种短 URL 必须保留）。改结构前先确认 URL 是否需要保持不变。

## 2. 内链格式（**重要，有硬约束**）

| 位置 | 格式 |
|---|---|
| **正文**（段落/列表/引用/提示框） | `[[docId\|label]]`（wiki 语法） |
| **表格单元格** | `[label](/url)`（markdown） |

**为什么表格里不能用 wiki：** 实测结论（2026-09-16）——
1. `[[id|label]]` 里的 `|` 被 GFM 表格解析器当列分隔符 → 单元格被切断 **且** 插件不再转换，页面直接输出裸 `[[...]]`
2. 转义写法 `[[id\|label]]` → 链接能生成，但 **href 尾部残留反斜杠**（`...有什么不同\`）→ 死链
3. 无别名 `[[docId]]` 在表格里可用，但 label 会显示成一长串 docId，不可接受

转换/校验脚本：`.workbuddy/unify_links.py`（表格感知）、`.workbuddy/check_guide_links.py`

## 3. 索引页

- **列表型索引页（含全部一级目录页）** → frontmatter 加 `hide_table_of_contents: true`
  （源码依据：`DocItem/Layout/index.js:27-31,45,59` —— 为 true 时 TOC 栏**整列不输出**，正文自动占满宽度）
- **退役**文档可用 `unlisted: true`（→ 侧栏移除 + `noindex`），不要删除文件
- 「退役又恢复」是允许的：曾把 `exness-trader/exness-trader`、`exness-agent/exness-agent`、`nytimes/nytimes` 用 `unlisted` 退役，同日又恢复为一级目录索引页（用户要求保留短 URL）

当前一级目录索引页（正文只有一行 `<SectionIndex ... />`）：

| 文件 | 说明 |
|---|---|
| `docs/index.mdx` | 首页，用 `<Homepage />`，`hide_title: true` |
| `docs/exness-trader/exness-trader.mdx` | 9 组 / 256 篇 |
| `docs/exness-agent/exness-agent.mdx` | 4 组 / 47 篇 |
| `docs/nytimes/nytimes.mdx` | 单组 / 5 篇（自动降级为胶囊样式，不渲染卡片网格） |

> 单分组规则：`groups.length === 1 && groups[0].name === "文档"` 时，组件**跳过卡片网格与 h2**，只渲染胶囊链接列表。

## 5. 构建与环境

- 无 `yarn` 时：`node node_modules/@docusaurus/core/bin/docusaurus.mjs build`
- **每一条 Bash 命令都要显式 export 完整 PATH**（含 `C:/Program Files/Git/cmd`、PortableGit `usr/bin`、node），**不要依赖 `$PATH`**（曾因 `$PATH` 未展开把 PATH 覆盖，导致 shell 工具全丢、git 找不到而构建报 `getGitFileInfo` 失败）
- 构建前**先停 `docusaurus serve`**，否则它占用 `build/` 会让构建卡死
- 构建失败后先清缓存再重跑：`node -e "for(const d of ['.docusaurus','node_modules/.cache','build']) require('fs').rmSync(d,{recursive:true,force:true})"`
- 干净重建可达 7 分钟（含 git log），**不要过早判定假死**；增量构建通常 11–25 秒
- 站点配了 `trailingSlash: false` → 产物是 `build/xxx.html` 而非 `build/xxx/index.html`
- Docusaurus 压缩 HTML 会**去掉属性引号**（`href=/xxx`），写校验正则时不要假定有引号
- `/tmp` 在不同 shell 下映射不同目录，日志可能找不到 → 直接检查 `build/` 产物

## 7. 工具调用：延迟工具（deferred tools）

MCP 工具（如 IMA）**不在直接工具列表里**，直接调用会报 "Tool Not Found"。
正确路径：
```
① ToolSearch(tool_names=["mcp__ima-mcp__fetch_media_content"])   ← 加载 schema
② DeferExecuteTool(toolName="mcp__ima-mcp__fetch_media_content", params={...})
```
- IMA 读取文件用 `media_id`（= 附件的 file id）
- 曾因此误判"IMA 不可用"，实际只是没走 ToolSearch

## 9. Frontmatter 规范（2026-09-16 定）

**必填**：`title`（≤25 汉字，主关键词前置，**不要写「汇鉴」**——模板会自动加 `\| 汇鉴`，手写会重复）、`description`（60–80 汉字，写成"点了能得到什么"的承诺句，**不要堆小标题**）

**可选**：`slug`（仅需自定义 URL 时）、`image`（每页独立 1200×630 分享图）、`sidebar_label`（只影响侧栏，长 SEO 标题靠它保侧栏可读性）、`sidebar_position`、`hide_table_of_contents`（列表型索引页设 true）、`last_update`（写了会**覆盖** git，慎用）

**必须写**：`date` —— ⚠️ **不是遗留字段**！本站 swizzle 的 `src/theme/DocItem/Layout/index.js:58` 用它生成 JSON-LD 的 **`datePublished`**。删掉会丢结构化数据的发布日期。
取值必须是**本站真实收录日期**，不要沿用源站日期。批量获取方式：
```bash
git -c core.quotepath=false log --diff-filter=A --format=%as -- <file> | tail -1
```

**不要用**：`keywords`（Google 已忽略）、`tags`（本站 `/tags/` 已被 robots 屏蔽）

**⚠️ 已知坑：git `core.quotepath`**
未设置（默认 `true`）时，git 对含中文的路径输出带引号 + 八进制转义（`"docs/xxx/\351\232\224..."`），而 Docusaurus 的 `getGitRepositoryFilesInfo()` 不做反转义 → **418/432 篇文档匹配不到 git 信息** → sitemap 无 `lastmod`、页面不显示「最后更新」、JSON-LD 无 `dateModified`。
**修复**：`git config core.quotepath false`（已于 2026-09-16 设置）
**⚠️ 这是仓库级配置，换机器或 CI 重 clone 后需重新设置，否则问题复发。**
**排查手法**：`require('@docusaurus/utils/lib/vcs/gitUtils.js').getGitRepositoryFilesInfo(root)` 打印 map key，看前缀是否带 `"`。

**⚠️ 已知坑：`lastUpdatedAt` 是毫秒**
`metadata.lastUpdatedAt` 已是**毫秒**时间戳，`new Date(x)` 直接用，**不要 `* 1000`**（会得到 `+058677-09-20` 这类垃圾年份）。该错误曾因 git 问题导致该值恒为 null 而被掩盖。

详见 `汇鉴-Frontmatter审查报告.md`（含完整执行记录）
