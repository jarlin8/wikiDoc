## 排查：`docs/nytimes/pu_prime_broker_research_report.mdx` 编译后不显示

**用户提问**：为什么 nytimes 目录下新建的文件编译后文章不显示？

### 诊断结论（全部实测）

| # | 原因 | 证据 |
|---|---|---|
| 1 | **侧栏未登记（根本原因）** | `sidebars.js` 的「纽时播报」分类只显式列了 5 篇，无此文件；`grep -c` 返回 0 |
| 2 | **URL 不在 `/nytimes/` 下** | 该文件 frontmatter 含 `slug: /pu-prime-broker-research-report` → 真实地址为站点根目录下 |
| 3 | **此前从未成功编译** | `build/` 目录 mtime 为 2026-09-10 16:57，早于文件创建时间 09-15 18:38；且 `build/` 中无该页面 |

**排除项**（实测）：文件名无隐藏字符；无 MDX 编译错误——实跑 `yarn build` **EXIT=0，59 秒**，页面正常生成（70KB）。

### 根因来源

9月10日第二批改动把 `sidebars.js` 从 `{type:'autogenerated', dirName:'.'}` 改为**显式分类树**。
副作用：**新增文档不会自动进入侧栏**，必须在 `sidebars.js` 中手动登记。

### 修复

在 `sidebars.js` 的「纽时播报」分类 `items` 中追加 `"nytimes/pu_prime_broker_research_report"`，
并加注释说明"新增文档必须显式登记"。重建后验证：`build/nytimes.html` 中出现
`<a href=/pu-prime-broker-research-report>`，侧栏收录成功。

### 附带澄清的知识点（易误判为 bug）

**Docusaurus 折叠状态的分类不会把子项渲染进首屏 HTML。**
- 实测：`build/index.html` 中搜不到「美硕移民」「赴美零碎知识点」等**原有**条目（计数均为 0），
  也搜不到本次新增条目 → 属正常行为，展开分类后由客户端渲染。
- 因此**不能**用"在 index.html 里 grep 不到"来判断侧栏是否收录；
  应改用**同分类内部页面**（如 `build/nytimes.html`）来验证，那里的分类默认展开。

## ⚠️ 环境事故与修复（重要，务必记住）

**事故**：执行 `export PATH="/c/.../node/...:$PATH"` 时 `$PATH` **未展开（为空）**，导致 PATH 被整体覆盖，shell 丢失所有 coreutils（`ls`/`head`/`tail`/`dirname` 全部 command not found），并连带 `git` 也不在 PATH 里。

**连带症状**：Docusaurus 构建报 `getGitFileInfo` 失败（`vcsGitEager.js`）——因为 `showLastUpdateTime: true` 需要 `git`。

**修复**：显式重建完整 PATH（**不要依赖 `$PATH`**）：
```bash
export PATH="/c/Program Files/Git/cmd:/c/Users/Jarlin/.workbuddy/binaries/PortableGit/versions/1.2.0/usr/bin:/c/Users/Jarlin/.workbuddy/binaries/PortableGit/versions/1.2.0/bin:/c/Windows/System32:/c/Windows:/c/Users/Jarlin/.workbuddy/binaries/node/versions/22.22.2-3"
```
- Bash 工具**不保留 shell 状态**，每条命令都要重新 export PATH
- 无 `yarn` 时改用：`node node_modules/@docusaurus/core/bin/docusaurus.mjs build`
- 清缓存（`yarn clear` 不可用时）：
  `node -e "for(const d of ['.docusaurus','node_modules/.cache','build']) require('fs').rmSync(d,{recursive:true,force:true})"`
- `/tmp` 在不同 shell 下映射不同目录，日志可能找不到 —— 用绝对路径或直接检查 `build/` 产物
- 干净重建耗时可达 **7 分钟**（含 git log 逐文件调用），不要过早判定为假死
