## Docusaurus 项目依赖与配置审查（docv2 + wikiDoc）

产出报告：`.workbuddy/reports/docusaurus-审查报告.md`（487 行，分「依赖更新分析」与「配置优化建议」两部分 + wikiDoc 附录）。

### 审查方法（可复用）
- 漏洞审计不依赖 `npm audit`（无 node_modules 时不可用）：解析 lockfile 提取「包名 → 已解析版本集合」，POST 到 `https://registry.npmjs.org/-/npm/v1/security/advisories/bulk`，再用自写 semver 区间比对剔除误报。脚本在 `%TEMP%/dcaudit/`（parse-lock.js 解析 Yarn Berry、parse-npmlock.js 解析 npm v3、verify.js 做版本命中确认、who.js 追溯引入方）。
- Git Bash heredoc 会吃掉正则里的 `\s`，写 JS 脚本必须用 Write 工具而非 `cat <<EOF`；`/tmp` 在 Git Bash 下映射为 `C:\tmp`（不存在），临时文件要用 `%LOCALAPPDATA%/Temp`。

### 关键结论
- **docv2**（3.10.2，Yarn 4）：直接依赖除 React 18→19 外全部最新。55 条公告（3 critical / 28 high / 21 moderate / 3 low，27 个包）**全部是 lockfile 陈旧解析导致的传递依赖**，且全部位于构建期，不进入浏览器产物。绝大部分可用 `yarn dedupe` + `yarn up -R` 零代码修复。3 个 critical：loader-utils 2.0.2、minimist 1.2.5、websocket-driver 0.7.4。
- 无法修复项：`image-size@2.0.2`（上游无补丁，latest 就是 2.0.2）、`serialize-javascript@6.0.x`（修复需 v7，被 terser-webpack-plugin 锁 ^6）、`uuid@8.3.2`（需跨到 11.x）。
- docv2 确定性缺陷 3 个：① `themeConfig.image: 'img/social-card.png'` 文件不存在 → og:image 全站 404；② CI `actions/checkout@v4` 缺 `fetch-depth: 0`，使 `showLastUpdateTime` 与 sitemap `lastmod` 失真；③ 根级 `onBrokenMarkdownLinks` 在 3.9 已弃用、v4 移除，须迁到 `markdown.hooks.onBrokenMarkdownLinks`。
- **wikiDoc**（3.9.2）问题更重：`docusaurus-theme-mdx-v2@0.1.2` 停更于 2022-07-20（v2 时代 MDX shim，3.x 原生 MDX v3，应删）；4 个未使用依赖（rehype-katex / remark-math / hast-util-is-element / walk-sync）；双 lockfile 并存且 yarn.lock 被 `@ai-sdk/*` 污染；CI 里 `yarn add @easyops-cn/docusaurus-search-local` 导致构建不可复现 + 供应链风险；`set NODE_OPTIONS=... &&` 是 cmd 语法，在 ubuntu CI 中被静默忽略 → 8GB 堆上限从未生效（425 个 mdx 有 OOM 风险）。
- wikiDoc 隐藏坑：`docusaurus.config.js:12–29` 的 `wikilink` 配置数组从未被引用（`remarkPlugins: [wikiLinkPlugin]` 传的是裸插件）。侥幸能跑是因为 remark-wiki-link-plus@1.1.1 内置默认值恰好一致（aliasDivider 默认 `'|'`、hrefTemplate 默认 `` `/${permalink}` ``）。**若"修复"接上这段配置，其 glob 只匹配 `.md` 而 docs 下 425 个文件全是 `.mdx`，557 处 wiki 链接会全部指向 `/404`。**

### 事实核对要点（已用官方文档验证，勿凭记忆）

### wikiDoc 补充结论（最终报告新增）
- **最高优先级两项（已抓线上页面验证）**：
  1. navbar `type:"html"` 注入 `<h1 class="font-extrabold">WikiDoc</h1>`，与每页正文 `<h1>` 并存 → 全站 425 页双 h1。
  2. frontmatter `description` 覆盖率仅 0.7%（3/425），其余由正文首行自动生成，摘要里带着 Markdown `- ` 符号。
- 扫描数据（425 个 mdx）：title 85.9%、tags 1.2%、无 frontmatter 60 个、wiki 链接 609 处、`<Ads>` 出现在 360 个文件、外链图片 testingcf.jsdelivr.net 340 处。
- 确定性代码缺陷：`custom.css` 的 `--ifm-font-famliy-base` 拼写错误（从未生效）、`--ifm-font-family-monospace` 被设成比例字体、`.footnote-ref{font-size:1px}`、`button` 全局蓝底白字；`ads.js` 用 Next.js `<style jsx>`（Docusaurus 不支持）+ 硬编码白底破暗色模式；`TOCItems` 广告无宽高（CLS）。
- CI：`--check-files` 是错误 flag（应为 `--check-cache`/`--frozen-lockfile`）；`actions/checkout` 缺 `fetch-depth:0`；push 无 `paths` 过滤。
- 已撤回的两条误判：jsDelivr 子域"慢 3.3 倍"（5 次采样中位数 1.40s vs 1.73s，无显著差异）；cdn.fendou.la"宕机"（实为本机 schannel 吊销检查 `CRYPT_E_REVOCATION_OFFLINE`，加 `-k` 后 200/0.88s）。
- sitemap 的 `changefreq`/`priority` 是搜索引擎已弃用字段；`static/wikiPrevBox/` 整目录 88 KB 为死文件；v4 迁移面内容侧几乎满分。

### 重大更正：悬浮预览弹窗是一条在线功能链路（用户指出后追查确认）
初版把 `static/wikiPrevBox/` 判为"死文件可整删"是**错的**——只看了引用计数，没追功能链。完整链路：
```
① remark-wiki-link-plus（构建期）→ 生成 <a class="internal new" href="/xxx">
② Docusaurus 输出 HTML
③ docusaurus.config.js:34-39 scripts 注入 /wikiPreviewBox.fixed.js（19KB，defer）
④ 运行期从 https://niu.fendou.la/wikiPrevBox/ 拉 min.css + w.svg + starlink.svg → 弹窗
```
**硬约束（勿再犯）**：
- `remark-wiki-link-plus` **必须保留**。源码 `dist/index.cjs.js` 中 `wikiLinkClassName` 默认 `'internal'`（:34）、`newClassName` 默认 `'new'`（:33）；`fixed.js:226` 用 `.internal:not(.LinkerLink-bound)` 作唯一挂载点。删插件 = 609 处 wiki 链接退化 + 弹窗全站失效。
- `static/wikiPrevBox/wikiPreviewBox.min.css` 与 CDN 那份 **MD5 完全一致**（4031f0092b016fbb906bee4d01a689cc / 3846B）→ 改自托管是零风险等价替换。

**源码级新发现**：
- 默认 `hrefTemplate`（:36-39）= `` `/${permalink}` ``（除非以 `#` 开头）；默认 `pageResolver`（:448-475）只做 `name.replace(/ /g,'-')`。故 `[[exness-trader/股票|股票]]` → `/exness-trader/股票`，与线上实测一致。
- 裸插件没传 `permalinks` → 退化为 `[]` → `exists` 恒 false → **609 处链接全部被误加 `new` 类**（语义是"页面不存在"，但实际存在）。
- 正确修法是用内置 `markdownFolder`（:476-478 `file.replace(/\.mdx?$/,'')`，递归读 cwd 下所有文件，**认 .mdx**），而非自己写 `pageResolver`。`remarkPlugins: [[wikiLinkPlugin, {markdownFolder:"docs", aliasDivider:"|"}]]`。
- `wikilink` 死配置（config:12-29）确认必炸：docs 下 **0 个 .md / 425 个 .mdx**，`walkSync` glob `**/*.md` 永不命中 → 全部返回 `/404`。且 `basename()` 还会丢子目录。

**fixed.js 自身缺陷**：
- :99-101 对所有 `[href*=wikipedia.org]` 无条件 `preventDefault()` → **全站 85 处维基外链点击无反应**。
- :257 `getLinkerPreviewData` 每次 hover 都 fetch 整页、无防抖无缓存（单页 HTML 130KB+）。
- :340 `setInterval(checkUrlChange,500)` 永久运行，与 popstate/pushState/MutationObserver 三重冗余。
- 弹窗内容选择器 `.markdown` 与 Docusaurus 的 `theme-doc-markdown markdown` 匹配，功能正常。

**数据规模**：wiki 链接 609 处 / 分布在 50 个文件；wikipedia.org 外链 85 处。
**教训**：判断"某文件是否为死文件"前，必须先追静态/全局 JS（尤其是 `static/*.js` 和 `scripts` 注入）里的**字符串选择器与运行时 URL**，不能只 grep 仓库源码引用。
