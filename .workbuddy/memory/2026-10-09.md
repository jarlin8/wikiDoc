## cookie 实测深入排查（同日上午）

用户提供真实 cookie（iwencai 登录态：userid=212484836，sess_tk JWT 有效期至约 2027-01）后继续实测，**cookie 不是最终瓶颈**：

| 实验 | 结果 |
|---|---|
| python requests + cookie（各变体：随机UA/ChromeUA/全套浏览器头/https/去v/核心字段） | 全部 403 HTML（openresty WAF） |
| curl（schannel TLS）+ cookie | 403 |
| curl_cffi 0.16.3 完整 Chrome 指纹 + cookie | 403（get-robot-data） |
| 浏览器实时 v= cookie 当 hexin-v 头 | 403 |
| **GET https://www.iwencai.com/（chrome 指纹，无 cookie）** | **200**（真 SPA 页面） |
| POST getDataList + chrome指纹 + cookie + **X-Requested-With + Referer + Accept** | **200**（业务层「组件不存在」-8302，参数不全所致） |
| POST getDataList + **node 自动令牌** + 同上三头 | **200**（同样过封锁） |
| POST get-robot-data + 全套头 + 两种令牌 | 仍 403 HTML（该接口有独立保护层） |

**结论**：
1. 排除 TLS 指纹假说（curl_cffi 也 403）、令牌时效假说（浏览器 v 也 403）。
2. 站点对**路由级**防护：GET 放行；getDataList（数据列表接口）只要带「AJAX 三头」（X-Requested-With/Referer/Accept）+ cookie + hexin-v 即穿透到业务层；get-robot-data（condition 接口）有更强的独立防护，pywencai 主链路被卡死在这。
3. hexin-v.js 内 `TOKEN_SERVER_TIME=1670329000.280`（2022-12）硬编码，但对 getDataList 无碍。
4. 可行架构（待验证）：用户浏览器抓一次 getDataList 请求（Copy as cURL）→ 提取固定问句的组件参数（condition/comp_id/uuid）→ 每日任务直连 getDataList 翻页取数，全程无需浏览器。问句固定所以参数大概率固定。
5. Plan B（如 uuid 为会话级短期失效）：弃问财，改 akshare/东财数据中心拿龙虎榜数据（东财反爬宽松）。
